# Catebi.ScheduleBot — функционал бота

Telegram-бот (Telethon/MTProto) приюта Catebi для записи волонтёров на смены и ежедневных отчётов по котоквартире. Данные хранятся в Airtable: таблицы `volunteer`, `schedule`, `notification`, `settings` + отдельная база стерилизации (таблица `cat_flat_fostering`). Интерфейс двуязычный (ru/en); все сообщения в топики группы — на русском.

Типы смен: `cleaning` (уборка котоквартиры), `cleaning_catloft` (уборка котолофта), `medical` (медуход), `steril_acceptance` (приёмка кошек), `steril_release` (выдача кошек). Доступные волонтёру типы определяются его `duty_codes` в Airtable (`kk_cleaning`, `kk_medical`, `steril_cat_in_out`, `kk_admin_curator` — признак куратора/админа).

## 1. Задачи по расписанию (aiocron)

| Cron | Время | Задача (файл) | Что делает |
|---|---|---|---|
| `0 0 * * *` | 00:00 | `daily_schedule_update` (`jobs/scheduling.py`) | Вызывает `update_volunteers("daily")`: перечитывает расписание из Airtable, пересобирает кэш «сегодня»/«будущие даты», редактирует закреплённые сообщения с общим расписанием в 4 топиках и заново их закрепляет |
| `0 * * * *` | каждый час | `send_curator_notifications` (`jobs/scheduling.py`) | Уведомления кураторам о нехватке волонтёров (логика ниже, п. 4.1) |
| `00 10 * * *` | 10:00 | `send_daily_cat_flat_status_notification` (`jobs/catflat.py`) | Обзор котоквартиры → в топик `process_notification_topic_id`; сохраняет снапшот состояния в `cat_flat_state.json` для вечернего сравнения |
| `00 11 * * *` | 11:00 | `send_daily_medical_notification` (`jobs/medical.py`) | Список кошек, требующих мед. внимания, + сегодняшний дежурный медухода → в топик `medical_topic_id` |
| `00 22 * * *` | 22:00 | `send_daily_cat_flat_changes_notification` (`jobs/catflat.py`) | Изменения за день (дифф с утренним снапшотом) → в топик `process_notification_topic_id` |

Кроме крона, при старте бота выполняется `update_volunteers("startup")` — обновляет кэш и создаёт отсутствующие закреплённые сообщения (без редактирования существующих).

## 2. Команды в диалоге

| Команда | Где работает | Что делает |
|---|---|---|
| `/start` | только ЛС | Показывает выбор языка; проверяет регистрацию в таблице `volunteer` (незарегистрированным — отказ), сохраняет язык и открывает главное меню |
| `/schedule` | ЛС и группы | В ЛС — главное меню с кнопками: «Записаться на смену», «Моё расписание», для вида "today" — «Общее расписание», для кураторов дополнительно «Нотификации» и «Нотификации приём/выдача». В группе — просто отвечает общим расписанием |
| `/settings` | только ЛС | Настройки: язык (ru/en) и вид главного меню (`today` — только сегодня / `general` — всё расписание) |
| `/help` | везде | Справка + версия бота |
| `/set_cleaning_topic`, `/set_medical_topic`, `/set_steril_cat_topic` | только кураторы | Отправляются в нужном топике супергруппы; сохраняют в `settings` chat_id группы (`topic_chat_id`) и ID топика (`cleaning_topic_id` / `medical_topic_id` / `steril_cat_topic_id`); подтверждение приходит в ЛС |
| `/set_alert_topic` | только кураторы, в группе | Отправляется в нужном топике супергруппы; сохраняет в `settings` chat_id (`alert_chat_id`) и ID топика (`alert_topic_id`), куда бот зеркалит логи уровня WARNING/ERROR (см. п. 5). Может быть отдельной группой от расписания. Применяется сразу и восстанавливается при старте; подтверждение — ответом в тот же топик |
| `/catflat_overview` | везде | Обзор котоквартиры по запросу (тот же, что в 10:00), ответом в текущий чат/топик |
| произвольный текст | только ЛС | Обрабатывается только когда куратор находится в режиме ввода кастомного текста уведомления (FSM в `state.custom_text_setting`); сохраняет текст, `{...}` нормализуется в `{}` для подстановки даты; команды `/...` отклоняются |

## 3. Callback-обработчики (кнопки)

Все нажатия проходят через `flows/dispatch.py` и разводятся по префиксу `event.data`.

### 3.1 Мастер записи на смену (`flows/schedule.py`)

- `new_schedule;<коды>` — если duties нет — ошибка; если несколько — выбор типа смены; для уборки — сначала экран выбора локации (сейчас в нём доступна только котоквартира; котолофт как тип существует, но кнопки записи на него нет). Затем список дат на 14 дней вперёд (`SCHEDULE_WINDOW_DAYS`) с индикатором занятости уборки (🆓/1️⃣/2️⃣); даты, на которые пользователь уже записан этим типом, скрываются.
- `set_schedule_time;<дата>;<тип>` — выбор часа (для сегодня — начиная со следующего часа). Не используется для приёмки кошек (там время не выбирается).
- `add_schedule;<дата>;<время>;<тип>[;<куратор>]` — создаёт запись в `schedule`, обновляет кэш и пины, подтверждает волонтёру, публикует сообщение о записи в соответствующий топик; если запись пришла из стерил-рассылки — дополнительно уведомляет куратора в ЛС.
- `my_schedule` — список своих будущих смен (нажатие на смену → удаление).
- `my_schedule_delete;<дата>;<тип>` — подтверждение удаления.
- `delete_schedule;<дата>;<тип>` — удаляет запись, обновляет кэш и пины, публикует сообщение об отмене в топик.
- `general_schedule` — общее расписание (сегодня + будущие даты).

### 3.2 Меню нотификаций куратора (`flows/notifications.py`)

- `notifications;;` — главное меню настроек; при первом входе создаёт запись в `notification` с дефолтами: `notify_at = 12:00`, `date_threshold = +1`. Варианты `notifications;unset;` / `notifications;reset;<тип>` — отмена ввода / сброс кастомного текста.
- `notifications_settings_text_menu` → `notifications_settings_text;<cleaning|medical>` — включает режим ввода своего текста уведомления (принимает следующее текстовое сообщение).
- `notifications_settings_notify_at` → `notifications_settings_notify_at;<HH:MM>` — час ежедневной проверки (сетка 00:00–23:00).
- `notifications_settings_date_threshold` → `notifications_settings_date_threshold;<+1..+6>` — на сколько дней вперёд проверять расписание.
- `notifications_send_menu` → `notifications_send;<cleaning|medical|all>;<дата?>` — ручная рассылка волонтёрам прямо сейчас; показывает счётчик «доставлено/всего».

### 3.3 Рассылка приёмки/выдачи кошек (стерилизация)

- `notifications_steril;;` — куратор выбирает выходные: ближайшие сб–вс, следующие, или свою дату (`notifications_steril_own_dates` — любая из 14 дней).
- `notifications_steril;<дата>` → предпросмотр текста → `notifications_steril_confirm;<дата>` — рассылка волонтёрам с duty `steril_cat_in_out`.
- `new_steril_acceptance;...` / `new_steril_release;...` — волонтёр из рассылки выбирает роль: приёмка (выбор одного из двух дней, без времени) или выдача (день, затем час); дальше стандартный `add_schedule` с уведомлением куратора.

### 3.4 Настройки и навигация (`flows/settings.py`)

- `language:<lang>` — смена языка; `change_language`, `change_view;...`, `change_view_to;<today|general>` — настройки; `back`, `back_settings`, `back_steril` — возврат в главное меню / настройки / к сообщению стерил-рассылки.

## 4. Нотификации: когда и по какой логике

### 4.1 ЛС куратору о нехватке волонтёров (ежечасный крон)

Каждый час бот берёт всех волонтёров с duty `kk_admin_curator` и их настройки из `notification`. Для куратора срабатывает только в час, равный его `notify_at`. Затем перебираются даты от сегодня до `+date_threshold` дней; для первой проблемной даты куратору отправляется ЛС:

- нет ни одной записи → «нет волонтёров вообще» + кнопка «разослать всем»;
- нет смены уборки → соответствующий текст + кнопка «разослать по уборке»;
- нет смены медухода → текст + кнопка «разослать по медуходу»;
- всегда добавляется кнопка «Игнорировать».

Уведомление отправляется только о ближайшей проблемной дате (после первой найденной — `break`). Кнопка сразу запускает рассылку `notifications_send;<тип>;<дата>`.

### 4.2 Рассылка волонтёрам (`services/notification_service.py`)

Запускается вручную из меню куратора либо кнопкой из п. 4.1. Получатели фильтруются по duty: `cleaning` → `kk_cleaning`, `medical` → `kk_medical`, `steril` → `steril_cat_in_out`, `all` → уборка или медуход. Текст — кастомный текст куратора или дефолтный, с подстановкой даты (переданной или «сегодня + date_threshold»); для `all` склеиваются оба текста. К сообщению прикрепляется кнопка «Записаться» (для steril — кнопки «приёмка»/«выдача»/«игнорировать»). Между отправками пауза 0.5 с (анти-флуд); возвращаются счётчики отправлено/всего.

### 4.3 Сообщения в топики группы при записи/отмене

При каждом `add_schedule`/`delete_schedule` бот публикует в супергруппу сообщение «@user записался/отменил <дежурство> <сегодня/завтра/дата> (время)» с эмодзи типа смены (🧹🏠 / 🧹🪜 / 🏥 / 😸⬆️⬇️). Топик выбирается по типу: уборка → `cleaning_topic_id`, медуход → `medical_topic_id`, приёмка/выдача → `steril_cat_topic_id`.

### 4.4 Закреплённые сообщения с общим расписанием

В 4 топиках (общий, уборка, медуход, стерил) висят закреплённые сообщения с полным расписанием («Сегодня: ...» + список будущих дат). Они создаются автоматически при отсутствии, редактируются после каждого изменения расписания (запись/удаление) и раз в сутки в полночь заново закрепляются. ID сообщений хранятся в `settings` (`last_pinned_*_message_id`).

### 4.5 Ежедневный статус котоквартиры (10:00)

Список всех кошек с активными статусами («принята в кд», «ожидает стерилизацию», «готова к выписке», «назначен медуход»), сгруппированный по комнатам с заполненностью (вместимость: K1 = 10, K2 = 10, Hall = 4, итоговый %). По каждой кошке: светофор по дням в квартире (🟢 < 7, 🟡 < 30, 🔴 ≥ 30, отсчёт от даты стерилизации или поступления), ссылка на заявку и карточку (Softr), статус, эмодзи 💊 (медуход) / 💉 (не полный мед. набор), заметки. В конце — кто сегодня на уборке и медуходе. Снапшот сохраняется в JSON.

### 4.6 Ежедневное мед. уведомление (11:00)

Кошки, требующие внимания: не обработана от блох (🦟), не привита (💉, с указанием нужной вакцины), не проглистогонена (𓆑) или назначен медуход (💊). Группировка по комнатам, внутри — по номеру заявки; для каждой — дни в квартире и ссылка на карточку. В конце — сегодняшний дежурный медухода (или «дежурного нет»). Если таких кошек нет — «всё в порядке».

### 4.7 Ежедневные изменения за день (22:00)

Сравнение текущего состояния с утренним снапшотом (10:00), секции: 🆕 новые кошки; 👋 выбывшие (для них статус/заметки дотягиваются из Airtable); смены статусов (сгруппированы «старый → новый»); изменения мед. отметок (🦟☑️/💉☑️/𓆑☑️). Если изменений нет — соответствующее сообщение; если снапшота нет/повреждён — сообщение об ошибке в тот же топик.

## 5. Служебное

- `update_volunteers(step)` (`services/schedule_service.py`) — центральный метод обновления: перечитывает `schedule`, строит списки «сегодня»/«будущее», обновляет/создаёт/перезакрепляет пины. Вызывается при старте, в полночь и после каждой записи/удаления смены.
- Все обращения к Airtable логируются (`airtable_logger`, лог `logs/airtable.log` с ротацией 10 МБ × 3); хендлеры обёрнуты декоратором `@logger` (логирует и пробрасывает исключения).
- **Алерты в Telegram (`alerts.py`):** логи уровня WARNING/ERROR зеркалятся в топик, настроенный через `/set_alert_topic` (`alert_chat_id` / `alert_topic_id` в `settings`) — мгновенное оповещение команды без внешних сервисов. Транзиентные WARNING-ретраи `urllib3`/`requests` в топик не шлются (только их ERROR+). Отправка не блокирующая и защищена от петель.
- **Трекинг ошибок (`monitoring.py`):** при заданном `GLITCHTIP_DSN` необработанные исключения и `logging.error` уходят в GlitchTip/Sentry (история, группировка, стектрейсы); без DSN — выключено.
- ID супергруппы хранится без префикса `-100` и дополняется им при обращении.
